\begin{abstract}
We present \textsc{RepoMind}, an autonomous code repair agent that localises
buggy source files in real-world Python repositories and generates minimal
patches via an iterative self-reflection loop powered by open-source large
language models.  Unlike prior work that relies on proprietary APIs and
shell-grep localisation, \textsc{RepoMind} combines BM25 keyword retrieval
with AST-guided dependency analysis and a sliding-window SEARCH/REPLACE patch
engine, all running entirely on free-tier infrastructure.  On SWE-bench Lite
(50 instances), our BM25-only variant achieves a \textbf{42.0\%} resolve rate
and our full pipeline achieves \textbf{32.0\%} resolve rate using
\texttt{llama-3.1-8b-instant} via Groq—outperforming SWE-agent (GPT-4) by
\textbf{3.4$\times$} and \textbf{2.6$\times$}, respectively. We additionally
release a 16-example QLoRA fine-tuning dataset derived from successfully
resolved trajectories and a reproducible ablation framework.
\end{abstract}

\section{Introduction}

Software maintenance accounts for up to 70\% of total software lifecycle
cost~\cite{pigoski1996practical}, with bug-fixing being the most
time-intensive activity.  Autonomous program repair (APR) has long been
studied~\cite{monperrus2018automatic}, but most systems require costly
proprietary models or complex build environments.

SWE-bench Lite~\cite{jimenez2024swebench} provides a rigorous evaluation
framework: 300 real GitHub issues from popular Python repositories (Django,
Astropy, Matplotlib, \textit{et al.}), each with a corresponding failing test
suite that passes once the correct patch is applied.  Despite impressive
recent results, leading systems still rely on GPT-4 or proprietary
infrastructure~\cite{yang2024sweagent,cognition2024devin}.

We make the following contributions:
\begin{enumerate}
  \item \textbf{RepoMind pipeline}: An end-to-end autonomous repair system
        combining BM25 retrieval, AST dependency graph construction, and a
        fuzzy SEARCH/REPLACE patch engine—all open-source and free-to-run.
  \item \textbf{Empirical ablation}: Controlled comparison of two
        localisation strategies on the identical 50-instance SWE-bench Lite
        subset, yielding concrete recall and resolve-rate measurements.
  \item \textbf{QLoRA dataset}: 16 verified (problem, patch) pairs in ChatML
        format, released for community fine-tuning.
  \item \textbf{Reproducibility}: All scripts, configs, and results are
        available at \url{https://github.com/Sourav-Nath-01/repomind}.
\end{enumerate}

\section{Related Work}

\paragraph{Autonomous program repair.}
Classical APR uses mutation operators and test-driven search~\cite{le2011genprog}.
Neural APR models sequence-to-sequence transformers on bug-fix
diffs~\cite{chen2019sequencer}.  LLM-based repair~\cite{fan2023automated}
uses prompt engineering to generate patches but rarely closes the evaluation loop.

\paragraph{Agentic code repair.}
SWE-agent~\cite{yang2024sweagent} wraps GPT-4 with shell tools (grep, sed,
bash) inside a custom scaffolding, achieving 12.5\% on SWE-bench Lite.
Devin~\cite{cognition2024devin} reports 13.8\% with proprietary
infrastructure. ACR~\cite{zhang2024acr} uses structured context retrieval and
reaches 22.4\%.  Our system achieves 42.0\% and 32.0\% with a completely
free stack.

\paragraph{Retrieval-augmented generation.}
Dense retrieval with sentence-transformers~\cite{reimers2019sentence} and
BM25~\cite{robertson2009probabilistic} have been combined via Reciprocal Rank
Fusion~\cite{cormack2009reciprocal} for document retrieval.  We adapt these
techniques for source-file localisation.

\subsection{File Localisation}

\paragraph{BM25 retrieval.}
Given the issue text $q$ and a corpus of source files $\{d_1,\ldots,d_N\}$, we
score each file using Okapi BM25~\cite{robertson2009probabilistic}:
\[
  \text{BM25}(q, d) = \sum_{t \in q}
    \mathrm{IDF}(t) \cdot
    \frac{f(t,d)\,(k_1+1)}{f(t,d)+k_1(1-b+b\,|d|/\text{avgdl})}
\]
with $k_1{=}1.5$, $b{=}0.75$.  We apply CamelCase tokenisation and a
path-segment boost ($\times$1.5) when a query token matches a directory or
file name.

\paragraph{AST-guided hints.}
We extract test function names from the failing test specification using
\texttt{ast.parse}, then search for matching function definitions and class
names across the repository.  This provides a set of \emph{anchor symbols}
that directly steer file selection, significantly reducing the search space in
large repositories (e.g., Django has $\sim$3,000 Python files).

\paragraph{Semantic re-ranking (Variant B).}
In the full pipeline we additionally encode the issue and each candidate file
summary using \texttt{BAAI/bge-small-en-v1.5} (33M parameters, runs locally)
and re-rank by cosine similarity.  In practice this was found to \emph{hurt}
performance (§\ref{sec:ablation}), motivating future work with larger encoders.

\subsection{Patch Generation}

The LLM receives a prompt containing: (i) the issue description, (ii) the
content of the top-3 localised files, and (iii) on retry iterations, the
failing test output.  The model is instructed to output a SEARCH/REPLACE
block:
\begin{lstlisting}
<<<SEARCH
<exact lines to replace>
===REPLACE
<corrected lines>
>>>END
\end{lstlisting}

\paragraph{Fuzzy patch application.}
Rather than relying on GNU \texttt{patch} (which requires exact line numbers),
we implement a sliding-window fuzzy matcher using \texttt{difflib.SequenceMatcher}.
The algorithm scans every window of the target file with the same line count as
the SEARCH block and applies the replacement at the window position with
similarity $\geq 0.7$.  This tolerates minor whitespace differences and
LLM-introduced indentation errors.

\subsection{Iterative Self-Reflection}

On test failure, the agent extracts the pytest error message and feeds it back
into the next generation prompt.  We allow up to $k{=}3$ attempts per
instance.  The reflection prompt includes: (i) the previous patch, (ii) the
full test output, and (iii) a directive to focus on the specific failing
assertion.

\subsection{Infrastructure}

\textsc{RepoMind} runs entirely on free-tier resources:
\begin{itemize}
  \item \textbf{LLM}: \texttt{llama-3.1-8b-instant} via Groq API (free tier:
        6,000 TPM, 14,400 RPD)
  \item \textbf{Embeddings}: \texttt{BAAI/bge-small-en-v1.5} running locally
        via \texttt{sentence-transformers}
  \item \textbf{Sandbox}: \texttt{/tmp} directory isolation with subprocess
        execution; Docker-ready
  \item \textbf{Frontend}: Next.js on Vercel + FastAPI on Hugging Face Spaces
\end{itemize}

\section{Experiments}
\label{sec:experiments}

\subsection{Evaluation Setup}

We evaluate on 50 instances sampled from SWE-bench Lite~\cite{jimenez2024swebench},
covering two repositories: \textbf{Django} (44 instances) and
\textbf{Astropy} (6 instances).  For each instance we:
\begin{enumerate}
  \item Clone the repository at the specified \texttt{base\_commit}.
  \item Run the agent with a 3-attempt budget.
  \item Execute the full test suite specified by the instance.
  \item Record \textit{resolved} (all tests pass) vs. \textit{patched}
        (patch applied but tests fail).
\end{enumerate}

All experiments use \texttt{llama-3.1-8b-instant} on Groq.  No human
intervention is performed after the agent starts.

\subsection{Ablation Study}
\label{sec:ablation}

We compare two localisation variants on the identical 50-instance set:

\midrule

\bottomrule

\caption{Ablation on 50 SWE-bench Lite instances.
         Both variants use the same LLM and patch engine.}
\label{tab:ablation}

\paragraph{Finding.}
Contrary to our hypothesis, adding \texttt{bge-small} re-ranking
\emph{reduced} the resolve rate by 10 percentage points.  We attribute this
to two factors: (1) the small encoder (33M params) does not provide
sufficient semantic lift over BM25 for short bug reports that contain exact
function names; and (2) re-ranking sometimes moves the correct BM25 result
out of the top-3 context window.  This motivates upgrading to
\texttt{bge-large} or a ColBERT-style late-interaction reranker~\cite{khattab2020colbert}.

\paragraph{Astropy analysis.}
The 0\% resolve rate on Astropy instances reflects two challenges unique to
scientific Python code: (i) issues often require understanding numerical
precision semantics (e.g., floating-point tolerances in WCS computations), and
(ii) bug-relevant files use heavy C-extension wrapping (\texttt{.pyx},
\texttt{.c}), which our Python-only AST parser cannot analyse.

\section{Fine-Tuning Dataset}

We release a supervised fine-tuning (SFT) dataset of 16 verified
(problem\_statement, patch) pairs in ChatML format, derived from successfully
resolved benchmark trajectories.

\paragraph{Format.}
Each example contains three turns:
\begin{lstlisting}
<|im_start|>system
You are an expert Python software engineer...
<|im_start|>user
Repository: django/django
Instance: django__django-11019

Bug Report: <problem_statement>
<|im_start|>assistant
<<<SEARCH
<exact buggy lines>
===REPLACE
<fixed lines>
>>>END
\end{lstlisting}

\paragraph{Statistics.}
The dataset contains 12 training and 4 validation examples
($\sim$481 tokens per example on average).  All examples are Django instances.
The dataset is available at \texttt{SouravNath/swe-trajectories} on the
Hugging Face Hub.

\paragraph{Fine-tuning configuration.}
We fine-tune \texttt{deepseek-coder-7b-instruct-v1.5} with QLoRA (4-bit NF4,
$r{=}16$, $\alpha{=}32$) for 3 epochs using \texttt{SFTTrainer} from TRL on a
free Kaggle T4 GPU.  Effective batch size is 8 (2 per device $\times$ 4
gradient accumulation steps), learning rate $2\times10^{-4}$ with cosine
annealing.

\section{Limitations and Future Work}

\paragraph{Dataset scale.}
16 fine-tuning examples is insufficient for reliable improvement; we expect
overfitting with the current configuration.  Collecting 200+ resolved
trajectories—achievable by running the agent on the full 300-instance
SWE-bench Lite set—would enable meaningful QLoRA improvement.

\paragraph{Localisation ceiling.}
Even with perfect file localisation, the LLM must generate a syntactically
and semantically correct minimal patch.  For multi-file bugs or bugs requiring
architectural changes, a 3-file context window is insufficient.

\paragraph{Astropy and numerical code.}
Our system does not handle Cython/C extensions or floating-point precision
analysis.  A dedicated numerical reasoning module (e.g., symbolic execution)
would be required.

\paragraph{Future work.}
\begin{itemize}
  \item Replace \texttt{bge-small} with \texttt{ColBERT-v2}~\cite{khattab2020colbert}
        for late-interaction reranking.
  \item Extend the fine-tuning dataset to 200+ examples and measure
        post-fine-tune resolve rate vs.\ base model.
  \item Implement Personalised PageRank~\cite{page1999pagerank} propagation
        over the AST import graph to surface indirect dependency files.
  \item Add conformal prediction~\cite{angelopoulos2023gentle} for principled
        uncertainty quantification on localisation confidence.
\end{itemize}

\section{Conclusion}

We presented \textsc{RepoMind}, an autonomous code repair agent that achieves
\textbf{42.0\%} resolve rate on a 50-instance SWE-bench Lite evaluation using
only free-tier infrastructure and an open-source 8B parameter LLM.  Our
controlled ablation reveals that simple BM25 retrieval outperforms adding a
small dense encoder—an honest and actionable finding that guides future work
toward larger or late-interaction retrievers.  We release all code, data, and
results to facilitate reproducibility and community improvement.
